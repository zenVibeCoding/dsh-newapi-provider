# New API Provider

[English](README.md) · 中文

DeepSeek Harness 的 New API 渠道与模型工作台。**开发中，尚未发布到 npm。**

## 能做什么

- 保存多个网关，每个渠道独立保存地址、凭据引用与模型参数；一次只激活一个。
- 在「渠道与连接」中新增、编辑、测试、激活和删除渠道。
- 查询令牌的剩余额度和已用量；无限额度显示累计已用，不展示无意义的负余额。
- 从网关发现模型，从 models.dev 补充上下文、输出上限和输入/输出能力。
- 在「模型能力」中搜索模型，直接编辑上下文、输出上限、模型类型、输入能力与显隐。
- 生图工具返回 DSH 图片附件；视频工具使用统一 `/v1/videos` 接口后台轮询。

## 环境与安装

目前验证环境为 DSH **0.2.1-rc.2**，Node.js 22.19 或以上；Web 与 Desktop 配置页通过 DSH 原生插槽显示。不需要单独启动网页服务器。

通过 DSH 的插件管理工具安装本地项目目录。安装后刷新现有 DSH 页面，打开「设置 → New API 提供商」。未发布到 npm 前不要直接执行 `npm install dsh-newapi-provider`。

本插件不依赖 `dsh-gateway-provider`。若需要保留旧会话的 provider 名称，可使用相同的 `providerId`，但不能让两个适配器占用同一路由。当前开发安装保留独立的 `newapi-provider` 路由。

## 从旧开发名称迁移（v0.7.0）

旧名称为 `dsh-newapi-studio`。此版本统一改为 `dsh-newapi-provider`：配置行与模型路由为 `newapi-provider`，HTTP 接口为 `/newapi-provider/api/`，数据目录为 `plugin-data/dsh-newapi-provider`。

已有安装迁移时需先备份配置和数据，再保留各渠道的 ID、凭据引用、模型清单及覆盖参数，将旧数据目录迁移至新名称。不要直接新装后丢弃旧配置；本版本不自动从旧目录读取。既有凭据引用即使含有 `STUDIO` 也应保留，新建引用使用 `NEWAPI_PROVIDER_` 前缀，无需复制令牌。

使用旧 `newapi-studio` 路由的会话需要重新选择新路由下的模型；其他适配器不受影响。工具名 `newapi_channels`、`newapi_models` 等保持不变。

## 渠道管理

1. 点击「添加渠道」，填写名称、New API 站点地址与调用令牌。
2. 「测试连接」只查询模型目录，不产生生成费用；能列出模型不代表上游渠道实际可调用。
3. 保存后点击「激活此渠道」，或勾选「保存后激活」。
4. 切换影响所有通过本插件路由发起的后续调用，不修改官方适配器或其他插件。
5. 已提交视频任务保持原始渠道，不应转向新激活的网关轮询。

现有单渠道 `baseURL` / `apiKeyEnv` 配置可继续读取；第一次在页面保存渠道时迁移到 `channels` 数组。凭据只经 DSH 凭据服务读写，不在渠道配置中存明文，也不把已有令牌发回浏览器。

模型覆盖属于渠道；在编辑器里修改参数时，绑定打开编辑器时的渠道。出现配置冲突提示后应刷新再编辑，避免覆盖另一个窗口的修改。

## 额度含义

- 主接口为 `GET /api/usage/token/`，注意末尾斜杠。
- 金额换算使用 `/api/status` 的 `quota_per_unit`、`quota_display_type` 和 `usd_exchange_rate`，不使用充值单价 `price`。
- 在 New API 为令牌开启「允许查询用户额度」后，较新版本可同时返回账户余额。
- 这些数字来自站点；模型目录存在、余额可查，都不保证站点已配置可调用的上游。

## 模型清单与测试（v0.3.0 起，v0.6.0 支持按渠道独立）

每个渠道独立维护自己的模型清单，即使两个渠道指向同一个站点、使用同一个令牌也互不影响：

- 「模型能力」页顶部有渠道切换器。激活的渠道带标记，编辑只作用于当前选中的渠道。
- 「获取模型列表」只读取网关目录。按对话／生图／视频分组，勾选后加入当前渠道的已启用清单。
- 新增渠道的清单默认为空；旧渠道兼容原自动模式，第一次添加或删除时按网关当前目录物化清单。
- 删除只影响当前渠道，不删除上游模型；可以保留自定义参数，并短暂提供撤销。刷新不会把删除的模型自动加回来。
- 「手动添加」适合网关未列出但可调用的自定义模型。已从网关下架的模型会单独标注，不自动删除。
- 对话模型测试发送一条很短的真实请求，**会产生调用费用**，显示总耗时、首包时间、最近结果和脱敏错误。首包时间不等于首字时间。
- 生图／视频测试每次需要二次确认，实际产生一个生成任务；视频提交成功只显示「任务已接受」，不等于生成验证通过。
- 批量测试只针对当前筛选下的对话模型，最多3个并发。停止阻止后续排队请求；已发出的请求仍会完成并可能计费。
- 当前测试器支持 OpenAI Chat、Responses 和 Anthropic Messages；Gemini专用协议测试会明确提示暂不支持，不会悄悄换协议测试。

## 模型名称映射（v0.4.0）

在模型编辑器的「名称与映射」中，三个名称各司其职：

- **本地模型 ID**：会话和已启用清单使用的稳定 ID，不在此处修改。
- **显示名称**（`name`）：只改变 DSH 中的显示。
- **上游映射模型名**（`upstreamModel`）：真实请求中的 `model`，留空使用本地 ID。映射只进行一次，不会递归追踪其他模型的映射。

例如本地模型 ID 为 `my-chat`、显示名称为「主力模型」、映射为网关支持的模型 ID，选择器和会话仍使用 `my-chat`，网关收到映射后的名称。对话、生图、编辑图片、视频及模型测试都使用同一映射。

编辑器显示请求映射预览。自动协议、能力、额度参数和定价优先从映射目标补全，手动覆盖仍然优先；输入能力可选自动或自定义，推理支持也可恢复为跟随目录。恢复默认会清除该模型的全部覆盖，包括上游映射。

当前映射有离线回归覆盖；未对真实上游追加付费映射调用。SDK 的模型专属请求兼容逻辑仍可能依赖本地 ID，所以跨厂商或跨模型系列映射需要检查协议、容量和能力是否合适。

## 模型与多模态

models.dev 数据有缓存。精确匹配优先，无法匹配时使用默认值；基础模型匹配、默认值与手动覆盖均在界面标出。切勿把猜测的能力当作网关实测结果。

DSH 当前对话接口只支持文本和图片输入。PDF、音频、视频标签表示目录元数据，不能据此直接向 DSH 对话发送这些内容。生图、视频模型供生成工具使用，不作为聊天模型出现。

## 工具

| 工具 | 用途 |
| --- | --- |
| `newapi_balance` | 查询当前激活渠道的令牌额度（允许时也含账户余额）。免费。 |
| `newapi_models` | 列出某个渠道的模型（`channelId` 可选，默认激活渠道），含类型、上限、多模态、定价与映射。免费。 |
| `newapi_channels` | `list`、`test`、`save`、`activate`、`delete`、`model_override`、`models_discover`、`models_set`、`model_test`；写入需要 `revision`。 |
| `newapi_image_generate` | 文生图；传 `inputImages` 时调用图片编辑接口，结果存为附件。 |
| `newapi_video_generate` | 提交视频任务并返回任务 ID，按任务计费。 |
| `newapi_video_status` | 列出或查询视频任务，返回已保存的文件。 |

设置页操作与这些工具共用同一套服务，界面与 agent 不会产生分叉。

**生图和视频可能扣费。** 提交结果不确定时不会自动重新提交；请先到网关任务日志核对。停止本地观察任务不代表取消网关端生成或退款。

## 付费结果保护（v0.7.1）

- 视频提交在收到响应头后断流、超时或响应不可解析，显示「提交结果未知，可能已计费」；不会自动重发提交。
- 视频上游已生成、仅下载失败时显示「已生成，等待下载重试」。仅重试 GET 状态/下载，重新获取可能过期的下载链接；下载恢复期限届满则显示「已生成，下载未成功」。不要因此重新生成。
- 同一任务的并发查询合并为一个请求流程，卸载时中止在途网络请求，防止旧实例覆盖新实例缓存。
- 模型测试必须有有效协议响应，仅有 `[DONE]` 不算成功。签名图片链接无法安全展示时仍记录已生成，不暴露签名链接；界面明确提示不要因没有预览而重复生成。
- 本轮只使用离线假网关回归。视频仍属实验性功能，尚无真实视频渠道完成端到端验证。

## 当前验证范围与限制

- 对话、目录与额度：已在本地 New API 上验证过。
- 生图真实调用曾返回 503「无可用渠道」；模拟网关的附件保存链路通过，真实生成成功尚未验证。
- 视频没有真实上游渠道，只做离线提交、后台轮询、下载、重启恢复与不重复提交测试，属于实验性能力。
- 页面最新视觉效果仍需在连接的 DSH 窗口确认；不能以插槽注册成功代替视觉验收。
